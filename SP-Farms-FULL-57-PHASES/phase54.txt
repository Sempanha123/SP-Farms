IMPORTANT NETWORK SAFETY RULE:
This phase supports persistent per-account VPN/Proxy profiles for privacy, testing,
organizational routing, and stable workspace configuration.

Do NOT implement:
- random IP rotation intended to evade Facebook security
- automatic country hopping to bypass restrictions
- anti-detect network fingerprint manipulation
- proxy rotation pools for mass-account evasion
- automatic changing of network identity to defeat platform controls

Each account may have a stable, operator-configured network profile.
The UI may remember a country/region label for that profile, but must not claim or spoof
a physical location unless verified by the configured connection.

======================================================================
PHASE 54 — PER-ACCOUNT VPN / PROXY NETWORK PROFILES
======================================================================

GOAL:
Make network configuration a first-class part of every account workspace.

The user should be able to:
- configure one network profile per account or per account group
- enable/disable it with a checkbox
- choose VPN, HTTP proxy, HTTPS proxy, SOCKS5, or system network
- remember the intended country/region label
- test it
- apply it BEFORE account restore
- block restore if the required profile cannot be established
- continue automatically into Restore Workspace and the selected Automation workflow
- never reselect the same account/Page/device

Example workflow:

Selected Account
    ->
Resolve AccountNetworkBinding
    ->
Network enabled?
    -> No: continue with system/default network
    -> Yes:
        Connect configured VPN/Proxy
        -> Verify connectivity
        -> Verify expected profile status
        -> If healthy, continue
        -> If failed and required, stop before opening app
    ->
Restore Workspace
    ->
Launch Preferred App
    ->
Run Selected Automation
    ->
Backup
    ->
Release Device
    ->
Next Account

6. RESTORE PIPELINE INTEGRATION
======================================================================

Update Restore Workspace pipeline.

Required order:

1. Resolve SelectionContext
2. Resolve Page -> Account if Page context
3. Reserve Device
4. Start Device if required
5. Wait for ADB
6. Resolve AccountNetworkBinding
7. If network enabled:
   - apply profile
   - wait for ready
   - health check
   - verify required conditions
8. Only after network gate succeeds:
   - restore safe workspace preferences
   - launch preferred app
   - check supported auth/session state
9. Mark Ready
10. Execute selected Automation steps

If network fails:
- do not continue when Require Network = true
- mark account/job `NeedsNetwork`
- show exact error
- release or retain device based on failure policy

10. PROVIDER ADAPTERS
======================================================================

Create NetworkProvider abstraction.

Possible built-in provider types:

A. System Network
No special connection.

B. Local VPN Client Adapter
Controls an operator-installed VPN client only through documented/local interfaces.

C. OpenVPN Profile Adapter
If an operator has a legitimate `.ovpn` profile:
- validate file path/reference
- launch configured local OpenVPN executable if supported
- wait for readiness
- stop cleanly
- keep secrets in vault/config-protected location

D. HTTP/HTTPS Proxy Adapter
Configure only through supported app/device/network mechanisms.

E. SOCKS5 Proxy Adapter
Configure only through supported app/device/network mechanisms.

Do not add stealth proxy injection.

======================================================================
15. SECRET HANDLING
======================================================================

Never store directly:
- VPN username/password
- proxy password
- private key
- certificate password
- auth token

Use vault refs.

For config files containing secrets:
- protect file
- reference it securely
- never include it in normal workspace backup
- include only through explicit encrypted secret backup flow

======================================================================
16. LIGHTWEIGHT BACKUP INTEGRATION
======================================================================

AccountWorkspaceSnapshot may contain:

- network_profile_id
- apply_before_restore flag
- require_network flag
- fallback policy
- country/region labels
- last known health metadata

Do NOT include:
- VPN password
- proxy password
- private keys
- secret config contents

On restore:
- resolve the NetworkProfile by ID
- verify required secrets are still available in vault
- if missing, show `NeedsNetworkCredentials`

======================================================================
17. QUEUE INTEGRATION
======================================================================

For account queues:

Account A -> Device 1 -> Apply Network A -> Restore -> Run -> Release
Account B -> Device 2 -> Apply Network B -> Restore -> Run -> Release
Account C -> waits
Account D -> waits

When Device 1 becomes available:
- scheduler picks next account
- resolves its own network profile
- applies its own profile
- proceeds only after network gate passes

Do not reuse the previous account's network profile accidentally.

======================================================================
18. CLEANUP / RELEASE
======================================================================

On Release Device:

Depending on preset:
- disconnect account-specific network profile
- restore system/default network state
- clear temporary proxy setting
- release device reservation
- mark device Available

This must run even after failures when safe.

Use `finally`-style cleanup semantics in job orchestration.
